# 需求文档: 商品批量导入 (Product Bulk Import)

## 1. 概述

- **一句话描述**：面向 SaaS 服务商的商品批量导入功能，运营人员上传 CSV 文件后，系统先解析并校验数据、展示预览结果，用户确认后按 Upsert 策略批量入库。
- **核心价值**：将逐条手工录入商品替换为一次性批量导入，显著提升商品维护效率；通过"先预览校验、再确认导入"保证数据质量，避免脏数据入库。
- **目标用户**：SaaS 平台的商家运营 / 商品管理人员。

## 2. 需求与用户故事

### 需求清单

| 编号 | 需求 | 优先级 |
|------|------|--------|
| R1 | 支持上传 `.csv` 文件并解析为商品记录 | 必须 |
| R2 | 固定表头严格匹配校验（12 列） | 必须 |
| R3 | 逐行数据校验（必填/数值范围/日期格式/文件内唯一） | 必须 |
| R4 | 导入前展示预览校验结果（合法行 / 非法行分类，含行号与错误原因） | 必须 |
| R5 | 用户确认后按 Upsert 策略入库（按 ProductID：存在则更新，不存在则新增） | 必须 |
| R6 | 确认导入时仅入库合法行，返回导入结果汇总（成功/更新/新增数量） | 必须 |

### 用户故事

- **US1**：作为运营人员，我希望上传一个 CSV 文件后能立即看到哪些行有问题、问题是什么，以便我修正后再导入。
  - **验收标准**：
    - 上传非 `.csv` 文件时被拒绝并提示格式错误；
    - CSV 表头与预定义 12 列不一致时，明确提示表头不匹配（指出缺失/多余列）；
    - 解析后返回预览：合法行数、非法行数，非法行逐条展示行号 + 具体错误原因。

- **US2**：作为运营人员，我希望校验通过后确认导入，系统按 ProductID 自动判断新增或更新，以便我批量维护商品。
  - **验收标准**：
    - ProductID 已存在 → 更新该商品字段；不存在 → 新增；
    - 仅合法行入库，非法行被跳过；
    - 导入完成后返回汇总：总行数、成功数、其中新增数、更新数、跳过数。

### 校验规则明细

| 规则类型 | 具体约束 |
|----------|----------|
| 必填字段 | `ProductID`、`ProductName`、`Category`、`Brand`、`Price` 不得为空 |
| 数值范围 | `Price` ≥ 0；`OriginalPrice` ≥ 0；`Stock` ≥ 0 且为整数；`Rating` ∈ [0, 5] |
| 日期格式 | `LaunchDate` 必须为合法 `YYYY-MM-DD` 日期 |
| 文件内唯一 | 同一文件内 `ProductID` 不得重复 |

> 字段全集（固定表头，顺序严格匹配）：
> `ProductID, ProductName, Category, Brand, Price, OriginalPrice, Stock, Rating, ReviewCount, SalesVolume, LaunchDate, Description`

## 4. 技术约束

- **技术栈**：Node.js + TypeScript 全栈（后端 API + Web 前端），全新从零搭建。
- **文件格式**：仅支持 `.csv`（UTF-8 编码，需正确处理中英文混排内容）。
- **数据规模**：单次 ≤ 1000 行，采用**同步处理**（无需异步任务队列 / 进度轮询）。
- **导入流程**：两阶段——① 上传解析 + 校验（返回预览）② 用户确认后正式入库。
- **导入语义**：Upsert，以 `ProductID` 为业务主键。
- **错误处理**：部分成功模型——预览阶段暴露所有非法行；确认导入时仅入库合法行并返回汇总。
- **数据存储**：需设计商品数据模型/表结构（含 12 字段），具体数据库选型在设计阶段确定。

## 5. 排除项

- ❌ 不支持 `.xlsx` / `.xls` 格式（本期仅 CSV）。
- ❌ 不支持可配置列映射（表头固定严格匹配）。
- ❌ 不支持 > 1000 行的大文件异步导入 / 任务队列 / 进度条轮询。
- ❌ 不支持"全量替换"或"仅新增/仅更新"以外策略（本期固定 Upsert）。
- ❌ 不涉及商品图片、SKU/多规格、多语言等扩展字段（仅样本 12 字段）。
- ❌ 不含导入历史记录 / 回滚 / 审计日志（如需可后续迭代）。
